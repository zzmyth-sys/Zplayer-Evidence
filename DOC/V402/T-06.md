## 1 结论

- 真实泄漏点：**SFF 加速器（HLS 转码服务）`infra/semaphore.py` 的 `stream` 与 `total` 许可池**；触发入口是 `app/scanner.py` 的 `slot("probe")`，不是 `tools/sff-server/sff_server.py:91` 的 `_sem`。
- 机理：事故镜像的 `acquire("probe")` 在拿到 `stream`+`total` 两个许可后执行 `_used[kind] += 1`，而 `_used` 没有 `probe` 键 → `KeyError`；`slot()` 的 `try/finally` 尚未进入，两个许可永久丢失。3 次 probe 即耗尽 `stream=3`，`total` 剩 1——与 V401 现场 `/frame` 仍成功、`used.stream=0` 完全吻合。
- 与“latest-wins 取消”无关：对旧码单独做“占满 3 许可 + 取消等待者 + 释放”实测，`stream` 仍回到 3；取消不是泄漏源。
- 当前部署已与 HEAD `c6ad7fd` 一致（`PermitPool` + `_bucket("probe")→stream`）：事故镜像可 100% 复现，当前线上不可复现。

## 4 A3 复现路径

### 4.1 事故镜像（可 100% 复现；本任务已在部署 runtime 实测，见 §5）

1. 服务空闲 ≥300 s（`config.py:95/109/111`：`SCANNER_ENABLED=1`、tick 30 s、confirm 300 s；`scanner.py:73-76` 要求无活动 stream）。
2. 一轮扫描有 ≥3 个新/变更文件 → `scan_once` → `_probe`。每个 probe：
   - `app/scanner.py:166 async with semaphore.slot("probe")`
   - `infra/semaphore.py:83 await acquire("probe")`
   - `:53 await pool.acquire()`（拿 stream）→ `:55 await p["total"].acquire()`（拿 total）→ `:60 _used["probe"] += 1` → **KeyError**
   - `:83` 在 `:84 try` 之前，`:86-87 finally: release` 不执行 → 两许可丢失；日志 `scanner probe failed: 'probe'`（`app/scanner.py:271`）。
3. 3 次 probe 后：`stream` 3→0、`total` 4→1、`used` 全 0。此时 `/frame` 仍可成功（frame 1 + total 1），与 V401 现场一致。
4. 用户请求序列：
   - `POST /stream/start {"uri":"<gop>2s 的源>","method":"transcode"}` → 返回 `streamId`。
   - `GET /hls/<streamId>/seg-0.ts` → `_generate`（`app/stream.py:286`）→ `run_ffmpeg`（`:300`）→ 旧 `app/encoder.py:172` → **卡在旧 `infra/semaphore.py:53 await pool.acquire()`（旧 acquire 无超时）**；`app/hls.py:74` 5 s `wait_for` 超时 → **504**；主机无 ffmpeg 子进程。
5. 快速切段 `GET /hls/<streamId>/seg-{N}.ts`（N 跳变）会触发 `app/stream.py:266 current.cancel()`（latest-wins），但**不是**本泄漏的触发点：同样取消时序在旧码实测 `stream` 仍回到 3（§5 `OLD cancel-waiter`）。

### 4.2 当前部署（HEAD `c6ad7fd`）

- 同一序列：`slot("probe")` → `_bucket("probe")="stream"`（`infra/semaphore.py:109-115`）→ 正常计数与归还；`/health` `available.stream=3`、`used.stream=0`。
- 取消安全：`acquire` 的 `:58 wait_for` + `:59-66` 归还；`slot` 的 `:156-162 finally` 归还。

## 6 A4 结论

**B（另一处信号量）**：真正未释放的是加速器 `infra/semaphore.py` 的 `stream`/`total` 许可；入口 `app/scanner.py:166 slot("probe")`，旧版 `:60 _used["probe"]` KeyError。

- 不是 A（当前部署落后）：当前 9/9 文件 sha256 = HEAD `c6ad7fd`；落后的是事故备份镜像（= `c6ad7fd^`），已不再运行。
- 不是 C（非信号量）：许可能量确实丢失，3 次 probe 后 `stream` 0 / `total` 1、`used` 0，可量化复现。
- 不是 D（无法复现）：事故镜像 + 部署 runtime 上已 100% 复现；当前码上不可复现，符合“已修复”而非“无法定位”。
