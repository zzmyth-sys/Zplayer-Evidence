# DEMO-SEEK-REAL — 四项补充实测（libsmb2 直读）

原始日志与完整口径见 `DOC/V402/DEMO-SEEK-DATA.md`；本文只放四项补充的结论表。
样本：`《小剧场》.mp4`，2160×3840 HEVC 60fps，39.34 Mbps，183.136 s，**861.2 MiB**，**GOP 2.5 s**；SURFACE 硬解；设备 MLR-AL00。
时钟：hilog（设备时钟）与 `/proc/net/dev`（同设备时钟）对齐。

## 一、环重置税：底层耗时 vs 端到端耗时

隔离样本 `FarBack`（90%↔10%，4 s 静默，网卡基线为 0），`wlan0 rx` 对 seek 时刻对齐：

| 事件 | far forward（跨 ~160 s） | far backward（回退 ~147 s） |
|---|---|---|
| 首包到达 | ≈100 ms（+111 ms 采样仍 0） | ≈80–100 ms（+104 ms 已 0.52 MB） |
| **渲染首帧（10008）** | **126 ms** | **90 ms** |
| **4 MiB 预取完成** | **≈110–140 ms**（插值） | **≈110–125 ms**（插值） |
| **16 MiB 环重置完成** | **≈220–250 ms**（插值） | **≈220–250 ms**（插值） |
| 单次 seek 网络拉取 | **29.8 MiB** | **30.3 MiB** |
| 理论所需（GOP 内 ≈2.1 s） | ≈10.5 MiB | ≈10.5 MiB |
| 网络放大 | **2.8×** | **2.9×** |

实测采样点（`wlan0 rx`，~70 ms 分辨率）：
- forward：+111 ms 0 MB｜+199 ms 6.32 MB｜+348 ms 25.67 MB｜+410 ms 29.81 MB
- backward：+104 ms 0.52 MB｜+179 ms 10.49 MB｜+251 ms 19.44 MB｜+379 ms 30.33 MB（停止）

结论：**16 MiB 环重置不是首帧延迟税，是带宽税。**
- 首帧由 256 KiB 块缓存兜底（`libsmb2.c:648-672`），所以 90–126 ms 就能上屏；
- 预取按 4 MiB 整块入 ring（`libsmb2.c:219-248`），4 MiB 完成 ≈110–140 ms，16 MiB ≈220–250 ms；
- 重置判据：前跳立即（`642-646`）、回退累计未命中 ≥1 MiB（`670-671`）；
- 风暴叠加效应：`BackForth` 48 次 seek / 8 s，网卡 **1171.6 MiB ≈ 1.36 个全片**，网络/协议层 1.73×。

在 fast/backforth 风暴中无法逐 seek 归因（网卡持续饱和 91–190 MB/s），因此隔离样本才是可引用的“4 MiB / 16 MiB 耗时”。

## 二、SeekArbiter 的 stale 丢弃有效性（快拖乱序）

`Fast`：50 请求 / 40 ms 间隔；合并窗 150 ms。

| 指标 | 结果 |
|---|---|
| 请求 → fire | 50 → **14**（合并 72%） |
| fire 实测间隔 | 160–190 ms |
| 拿到 10008 | 7/14（其余被后续 serial 覆盖） |
| `stale_gen` | 9/14（仅是 DEMO 标签，不撤销 native seek） |
| 渲染位置序列 | 7675→22620→…→157170→170629（**严格单调**） |
| 位置回跳 | **0** |
| 迟到回调 | seq11 的 10008 迟 317 ms（晚于下一次 fire 97 ms） |
| 黑帧 | 无 `noFrame`；但未做逐帧截图，不能断言无黑帧 |

结论：150 ms 窗**有效**（72% 抖动未下发 native，native seek 压到 14 次/2 s）；`stale` 只用于日志，真正的互斥由 ffplay serial 完成；观察到迟到 ack，**未观察到画面回跳**。但 10008/600 都不带 id，风暴中“ack 归属”不可判定（seq11 的 317 ms 大概率是错绑）——这正是 T-20 票据要补的洞。

## 三、读放大：直读 vs 代理

| 口径 | DEMO 直读 | 主项目 B 链（代理） | 判定 |
|---|---|---|---|
| 20 连拖（8 次 native seek，1.2 s） | **111.9 MiB**（+2 s 内 161 MiB） | 30 Range / **880 MiB** | DEMO 更低 |
| 48 seek 风暴（8 s） | **1171.6 MiB**（1.36× 全片） | 880 MiB / 30 Range | DEMO 总量更高（seek 数 1.6×） |
| 每次受理 seek 网络字节 | 14.0（burst）/ 24.4（backforth）/ ≈30（远距） | 29.3 MiB/Range | 基本持平 |
| 每次受理 seek 协议层字节 | 5.75（burst，ack 中位）/ 6.7 / 6.5–11.4 MiB | — | — |
| 网络/协议冗余 | **1.51×（burst）/ 1.73×（backforth）** | 未知 | 环重置导致 |

结论：不存在“异步预取显著比 Range 碎片更费带宽”的普适结论；单次操作同量级，**高频反向/远距**时 16 MiB 环重置会把总流量推到全片以上，这是 Range 代理没有的成本。

## 四、落点偏差极值（T-20“唯一真源”）

| 口径 | 偏差 | 可用性 |
|---|---|---|
| `OnSeekComplete` 内 `getCurrentPosition()` | +0…+7 ms | **不可用**（seek_pos 回显） |
| 10008 时刻 `getCurrentPosition()`（accurate=off） | −2194…+227 ms；孤立远距稳定 −2.05~−2.19 s | 中（受音频/主时钟影响，量级=GOP） |
| `10100 pts`（accurate=1） | −861…−702 ms | 中高（IJK 自带 pts，含音频握手偏置） |
| J8 逐帧截图对比 | **未做** | — |

- GOP=2.5 s → non-accurate 落点必然落在 `[target−2.5 s, target]`；实测 −2.19 s 属“关键帧对齐”，不是 seek 失败。
- 对比主项目 −6.9 s/+3.5 s：DEMO 误差被限制在**一个 GOP 内**，量级 1/3–1/2；但未达帧级（accurate 仍 −0.8 s）。
- 对 T-20：`getCurrentPosition()` 不能当唯一真源（回显目标）；候选真源是“10008 时刻时钟”与“10100 pts”，两者都需零点标定；唯一无偏口径是 J8，尚未做。
